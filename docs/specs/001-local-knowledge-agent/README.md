## 文档目的

本规范用于将项目从“带长期记忆的通用聊天产品”收缩为“本地知识整理 Agent”。目标系统监听本地文件和开发工具会话，经过解析、去噪、分块、去重、知识提取、质量审查和索引构建，最终产出用户可以直接阅读、检索并追溯来源的学习资料。

规范将需求、技术设计和实施任务拆开管理。任何技术方案只有同时具备需求编号、验收标准和验证任务，才视为可实施需求。

## 一句话定位

这是一个事件驱动的本地知识整理 Agent：它观察文件变化，选择处理路径，执行知识加工工具，评价结果质量，并发布带来源引用的学习资料供用户检索和阅读。

## 目标范围

### 保留

- 本地文件和开发工具会话目录监听。
- Markdown、文本、JSONL、Codex、Claude Code、Cursor 会话解析。
- 归一化、去噪、分块、词法去重和语义去重。
- LLM 辅助的知识提取、主题分类和质量判断。
- `accept / review / reject` 三态质量闸门和持久化审计队列。
- Markdown 知识文件作为人类可读的主数据。
- SQLite 元数据、任务队列、关键词和向量索引状态。
- USearch HNSW 近似向量检索，以及 JavaScript 精确检索降级。
- 关键词、向量、标签、图谱、多路查询改写和 MMR 重排。
- 来源配置、处理状态、审核、检索、主题阅读和知识详情界面。

### 删除或停用

- 通用聊天页面和聊天 API。
- 聊天会话历史及会话分支。
- 用户画像推断、画像演化和画像页面。
- 基于画像标签的个性化排序。
- 面向聊天人格的 Prompt 管理页面。
- 面向聊天的 MCP 和 Skills 工具调用。
- 浏览器历史和书签采集。
- 只服务于聊天模型路由或画像维护的后台任务。

### 不得误删

- `KnowledgeModelAdapter`：知识提取、主题分类、质量检查和 Embedding 仍然依赖独立模型边界。
- 审计队列：模型生成内容不得绕过质量审查直接落盘。
- 降级机制：没有模型时仍需支持本地解析、浏览和关键词检索。
- 来源追踪：每个知识单元必须能追溯到原始文件或会话。

## 当前代码规模基线

Phase 0 格式基线统一后，当前 `src` 下约有 33,942 行非空 TypeScript/TSX，其中单元和集成测试约 7,580 行，检索评测约 593 行。产品实现及样式约 27,014 行。聊天、Prompt、画像、MCP/Skills 和浏览器采集等第一批候选模块约占 4,976 行，尚未计算删除后可以继续合并的共享代码。

代码行数只用于评估工作量，不是最终目标。改造是否成功取决于依赖关系是否清晰、主链是否闭环、是否容易验证和讲解，而不是是否达到某个固定行数。
