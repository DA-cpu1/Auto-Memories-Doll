## 1. 交付结果

主题学习资料现在以 `memory-root/guides/{topic}.md` 发布。每份资料包含有序大纲、章节、知识 ID、来源版本集合、内容哈希和生成时间，并保留机器可校验的结构化载荷。`GET /api/topics/[topic]` 读取既有资料，`POST /api/topics/[topic]` 支持确定性重建及可选模型辅助。

## 2. 确定性生成

`StudyGuideBuilder` 只加载 SQLite 中已发布的同主题知识，按共享标签和主题内图谱关系分组，再以稳定标题和 ID 排序。章节正文只由知识标题与摘要组成，每条知识恰好在一个章节中出现。LLM 不可用时此路径完整可用。

## 3. 模型边界与引用验证

可选标准模型只接收已接受知识的 ID、标题、摘要和确定性章节，只能返回原章节的新标题与顺序。章节集合、章节内知识集合或引用发生增加、删除、重复和替换时，模型结果整体拒绝并回退确定性资料。运行时 Zod schema 还会复验：

- 大纲只引用真实章节；
- 每章至少引用一条知识；
- 每条知识恰好被引用一次；
- 每条知识至少关联一个来源版本；
- 内容哈希和时间格式合法。

旧知识缺少统一来源关系时使用明确的 `legacy-source-*` 与 `memory-{id}-v{version}` 兼容标识，不伪造外部来源版本。

## 4. 发布与增量刷新

发布先在目标目录写唯一临时文件，重新读取并执行完整 schema 与哈希校验，通过后才原子替换正式 Markdown。生成前比较不含时间戳的内容哈希，知识集合和组织结果未变化时保留旧文件，不产生无意义写入。

`Orchestrator` 在批量发布、删除、全量采集重建和冲突解决后，只把实际变化的 topic 交给生成器。`guides/` 已加入 watcher 和手动扫描排除范围，避免派生资料被重新采集。

## 5. 验证

- `npm run typecheck`
- `npm run lint`
- `npm test`
- `npm run build`

专项测试覆盖确定性结果、完整来源引用、合法模型调整、非法引用回退、原子 Markdown 往返和增量主题去重。Phase 7 可以直接使用主题 API 构建资料阅读页。
