# 产品需求规范：本地知识整理 Agent

| 字段     | 内容               |
| -------- | ------------------ |
| 规范编号 | `LKA-001`          |
| 状态     | 已确认             |
| 优先级   | 实习作品集核心项目 |
| 目标版本 | 功能收缩版本       |

## 1. 问题定义

开发者会在本地 Markdown、普通文本和开发工具对话中积累大量有价值的信息，但这些内容混杂着重复日志、临时调试记录、被放弃的方案和不完整片段，之后很难重新利用。普通文件搜索无法找到语义相关内容，而通用聊天入口又会遮蔽真实来源，使项目范围膨胀并难以完整讲解。

项目需要收缩为一个目标明确的本地 Agent：持续监听受支持的数据源，将噪声内容加工成可追溯、可阅读、可检索的学习资料。

## 2. 项目目标

- 自动观察用户配置的本地目录和开发工具会话目录。
- 将含噪原始资料转换为独立且带来源引用的知识单元。
- 防止重复、低质量或不确定内容静默污染知识库。
- 将通过审核的知识单元组织为适合直接阅读的主题学习资料。
- 不依赖聊天，通过检索库、主题和知识详情完成查阅。
- 在 LLM 或 Embedding 不可用时继续提供有效的本地能力。
- 将核心代码范围压缩到能够在实习面试中完整解释和维护的规模。

## 3. 非目标

- 提供通用 AI 聊天。
- 保存、恢复或分支聊天会话。
- 从聊天中推断用户心理、偏好或能力画像。
- 使用推断画像对检索结果进行个性化排序。
- 作为通用 MCP 客户端或 Skills 执行平台。
- 提供云端多用户知识同步服务。
- 修改或替代用户的原始来源文件。
- 使用模型自身知识生成没有本地引用的长篇文章。

## 4. 目标用户

### 4.1 学习者或开发者

配置本地目录，让 Agent 自动处理资料，通过关键词或自然语言检索知识，并阅读带原始来源的主题学习文档。

### 4.2 审核者

查看不确定或冲突候选，对照来源决定接受、编辑或拒绝。对于本地单用户应用，学习者和审核者可以是同一个人。

## 5. 核心用户流程

### UJ-01：自动采集本地资料

1. 用户添加一个受支持的本地目录。
2. Agent 检测到新增或修改文件。
3. 页面展示该来源的处理阶段和结果。
4. 通过审核的内容自动出现在检索库和主题学习资料中。

### UJ-02：处理不确定内容

1. 质量闸门将候选判定为 `review`。
2. 用户进入审核队列。
3. 页面展示候选内容、原始来源、判定原因和相似知识。
4. 用户接受、编辑后接受或拒绝该候选。

### UJ-03：阅读主题学习资料

1. 用户打开一个主题。
2. 系统展示有顺序的主题大纲、章节和相关知识单元。
3. 每个章节都可以查看其依据的知识单元和原始来源。

### UJ-04：混合检索

1. 用户输入自然语言查询。
2. 系统并行执行关键词、向量、标签和可选图谱检索。
3. 系统合并结果并执行多样性重排。
4. 用户打开结果时可以查看命中原因和来源。

### UJ-05：离线或模型降级

1. 模型服务不可用。
2. 系统继续监听和执行确定性处理，将依赖模型的工作安全暂存。
3. 既有学习资料仍然可以浏览和关键词检索。
4. 页面明确显示哪些能力正在降级。

## 6. 功能需求

### 6.1 采集

- **FR-001 来源配置**：用户必须能够新增、停用、编辑和移除监听来源。来源配置至少包含类型、根路径、包含规则、排除规则和启用状态。
- **FR-002 自动观察**：启用的来源必须支持新增、修改以及适用的删除事件。短时间连续写入必须经过稳定窗口合并。
- **FR-003 输入格式**：目标版本必须支持 Markdown、普通文本、JSONL 工具会话，以及项目已有的 Codex、Claude Code 和 Cursor 会话解析。
- **FR-004 稳定身份**：每个来源和来源版本必须具有稳定标识。重复观察未变化的来源版本必须成为无操作事件。

### 6.2 知识加工

- **FR-005 归一化和去噪**：进入知识提取前必须完成内容归一化。系统必须去除控制字符、空对话、重复块、已知工具样板和无效编码，同时保留来源信息。
- **FR-006 分块**：大文件必须优先按照 Markdown 章节、对话轮次等语义边界分块，最后才按长度切分。块大小和重叠量必须可以配置并具有确定性默认值。
- **FR-007 去重**：系统必须先执行低成本的精确和词法去重，再按需执行语义去重。达到语义重复阈值的候选不得作为新知识发布。
- **FR-008 知识提取**：有效内容必须能够转换为一个或多个结构化候选，包括标题、摘要、正文、标签、主题、来源引用和时间戳。
- **FR-009 主题分类**：Agent 必须为候选分配稳定主题。规则分类作为基础路径，LLM 可以参与复核；模型失败时必须回退到已知分类。
- **FR-010 质量评价**：每个候选必须得到结构化的 `accept`、`review` 或 `reject` 结果，并携带分数、原因代码和人类可读原因。评价不可用或输出非法时必须进入 `review`。
- **FR-011 审计后发布**：只有自动接受或人工明确接受的候选可以写入正式 Markdown 和索引。候选状态必须能够跨进程重启恢复。

### 6.3 学习资料

- **FR-012 知识单元发布**：每个通过审核的知识单元必须保存为带 YAML 元数据和稳定 ID 的自包含 Markdown 文件。
- **FR-013 主题学习资料**：系统必须按主题维护可直接阅读的学习资料，至少包含大纲、有顺序的章节和知识单元引用。
- **FR-014 增量更新**：来源版本变化时，系统必须更新或替代受影响的知识单元和主题资料，不得重建无关主题。
- **FR-015 来源展示**：知识详情和主题资料必须展示来源类型、来源路径或来源标识、采集时间和来源版本。

### 6.4 检索

- **FR-016 混合检索**：搜索必须包含关键词和向量通道；在对应索引可用时，应支持标签过滤、查询改写、图谱邻居和 MMR 多样性重排。
- **FR-017 结果可解释**：每条结果必须包含主题、来源、最终相关度以及参与命中的检索通道。
- **FR-018 直接阅读**：用户必须能够浏览全部主题、打开主题资料、打开单个知识单元并沿内部链接继续阅读，全程不依赖聊天。
- **FR-019 检索评测**：必须使用版本化数据集测量 Recall@k 和 MRR，低于已确认阈值时评测命令必须失败。

### 6.5 运行与维护

- **FR-020 人工审核**：用户必须能够列出并处理 `review` 候选和内容冲突。
- **FR-021 索引重建**：用户必须能够从规范数据重建关键词、图谱和向量索引，且不得修改已经接受的 Markdown 知识正文。
- **FR-022 降级状态**：应用必须分别展示 LLM 和 Embedding 的降级状态，并定义各处理阶段在降级时的行为。
- **FR-023 可审计日志**：处理日志必须关联来源 ID、来源版本、事件 ID、阶段、结果、耗时和错误类型。

## 7. 非功能需求

- **NFR-001 本地安全**：默认服务必须绑定 `127.0.0.1`，默认配置下拒绝非本机 Host。
- **NFR-002 数据耐久性**：进程意外终止不得丢失已入队候选，也不得留下损坏的正式 Markdown。
- **NFR-003 幂等性**：在来源没有变化时连续执行两次全量扫描，最终知识单元集合必须一致。
- **NFR-004 响应性能**：文件稳定窗口结束后，处理状态应当在两秒内可见；在演示数据集且向量已建立时，搜索应在 500 ms 内返回。
- **NFR-005 可移植性**：Windows 是主要本地环境；核心路径处理和测试数据必须兼容 Linux CI。
- **NFR-006 可访问性**：保留页面必须支持键盘导航、可见焦点、语义标签和无横向溢出的移动端布局。
- **NFR-007 可维护性**：核心采集、检索和存储模块禁止导入 React 或 Next.js Route Handler。
- **NFR-008 可解释性**：每次自动拒绝或转人工审核必须同时提供用户可读原因和测试可断言的结构化代码。

## 8. 验收场景

### AC-001：新来源形成知识单元

**假如**已启用的 Markdown 来源中新增了一份有效技术笔记，**当**文件写入稳定后，**那么**系统只生成一个稳定事件，完成质量评价，发布一个知识 Markdown，并让关键词和向量索引引用同一个 ID。

### AC-002：重复观察不产生副本

**假如**某来源版本已经处理完成，**当** watcher 重启或用户执行扫描再次发现该未变化文件时，**那么**系统不得创建新知识单元或重复队列事件。

### AC-003：不确定结果禁止发布

**假如**提取或质量模型返回非法或不确定结果，**当**系统处理该事件时，**那么**事件必须进入 `review`，不得创建正式 Markdown，并允许用户查看原因。

### AC-004：Embedding 降级

**假如** Embedding 服务不可用，**当**用户搜索既有资料时，**那么**关键词和元数据结果仍然可用，页面必须显示向量能力降级。

### AC-005：来源可追溯

**假如**用户正在阅读主题资料中的一个章节，**当**用户查看该章节依据时，**那么**至少可以看到一个知识单元引用及其来源版本。

### AC-006：索引重建安全

**假如** ANN 或关键词索引丢失、不一致或损坏，**当**用户请求重建时，**那么**系统必须从规范记录重新生成索引，并保持已接受知识内容不变。

### AC-007：被删除功能不可访问

**假如**已部署功能收缩版本，**当**用户检查导航和 API 契约时，**那么**聊天、聊天会话、人格 Prompt 和画像接口必须不存在。

## 9. 成功指标

- 所有必需验收场景具有自动化测试或明确可复现的人工验证步骤。
- 检索评测达到已提交的 Recall@k 和 MRR 基线。
- 未变化来源重复扫描时，新增重复知识数量为零。
- 演示数据集中每个正式知识单元都有合法来源。
- 生产代码中不存在对聊天或画像模块的依赖。
- 类型检查、严格 Lint、单元和集成测试、生产构建及浏览器 E2E 全部通过。
- 可以在五分钟内完成完整演示：配置来源、添加文件、观察加工、打开主题资料、执行搜索、追溯来源。

## 10. 待确认的范围决策

本规范提出以下默认决策：

1. 保留现有知识图谱，将其作为可选的检索和导航通道。
2. 从默认产品中删除浏览器历史采集，使隐私边界更加集中。
3. 删除面向聊天的 MCP 和 Skills；未来只有在作为类型化采集适配器时才重新引入 MCP。
4. 保留人工审核页面，因为 fail-closed 质量策略必须具有人工出口。
5. 主题学习资料只能依据已接受的本地知识单元生成，禁止混入无引用的模型背景知识。
