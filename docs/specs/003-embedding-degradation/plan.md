# KA-003 技术设计

状态：已实施，验收结果见 delivery.md。运行数据迁移必须通过预览后的显式确认操作执行。

## 能力边界

保留 KnowledgeModelAdapter 作为唯一模型入口。健康信息按 budget、standard、flagship、embedding 槽位独立维护，配置指纹改变使对应故障失效。Embedding enabled 缺省为 true，false 时生成、探测和补建均不调用远端。实际请求失败返回结构化依赖原因；网络退避与缺少配置分别处理。健康探测使用固定文本，按槽位独立执行。

## 队列与恢复

pending_events 增加 waiting_dependency 状态及 JSON dependency 字段，保存槽位、阶段、原因、attempts、lastAttemptAt、nextAttemptAt、paused。正常消费只领取 pending；等待到期后有界唤醒，每批上限 20。1、5、20 分钟后最多重试三次，配置错误直接暂停。进程恢复只恢复 processing，不改等待预算。等待列表与 review 分开查询。消费锁覆盖同一进程的知识循环；同一 memoryId 按 createdAt 消费。

质量和提取故障进入等待，内容 review 保留原规则。已通过的加工阶段以候选内容 hash、模型配置和策略版本为键缓存；键变化时重新执行。更新在完成模型加工前保留旧版，发布前校验来源与内容版本，陈旧候选显式拒绝并记录被替代原因。

## 无向量加工

精确身份使用未经破坏性归一化的正文 SHA-256（保留中文、符号、数字和否定词）。排除自身记录。跨来源重复关系保存在独立引用表，原候选与来源记录不删除。未完成的相同候选串行确定归属。关键词召回使用有限本地候选，仅向 LLM 提供参考，注明没有语义新颖性保证，不生成 cosine 分数。读取失败抛出存储错误。

## 向量补建

持久化每条已发布记忆的向量状态和目标内容 hash、模型、维度；后台有界补建只写向量索引。异步结果提交前再次核对当前记忆、配置与 enabled。内容删除、变更或模型切换后丢弃旧结果，不触发 Markdown 发布。

## 旧队列兼容

预览仅选择 review 且纯 VECTOR_RECALL_UNAVAILABLE、无人工动作、来源仍存在的候选。Codex 必须有 KA-002 策略证据。预览保存事件与内容指纹，执行事务内重验。批次、项目状态和检查原因持久化；重复执行幂等，支持暂停和重启恢复。迁移只转入正常加工，不接受候选、不启动来源。

## API 与界面

集中登记等待查询/重试及迁移预览/执行/暂停契约。首页按当前队列状态分别计数，进度增加 waiting_dependency。设置提供 Embedding 开关，能力提示区分知识加工和语义召回。等待列表显示任务、原因和预算；迁移操作必须展示预览结果。
